# Release policy

- Release from a reviewed, protected branch and a known commit.
- Require green CI, approved changes and resolved release-blocking findings.
- Use semantic versioning where the product's compatibility model supports it.
- Publish release notes with changes, migration notes and known issues.
- Verify artifacts and provenance where supported.
- Define deployment health checks, monitoring and rollback before production rollout.
- Production deployment and publication require explicit human approval unless a project-specific policy has separately authorized them.
