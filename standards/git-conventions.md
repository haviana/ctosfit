# Git conventions

- Use short-lived branches: `feat/`, `fix/`, `chore/`, `docs/`, `refactor/`.
- Use Conventional Commit-style messages: `type(scope): imperative summary`.
- Keep commits focused and explain non-obvious decisions.
- Pull requests must describe intent, behavior, risks and verification.
- Require CI and at least one independent approval for protected branches.
- Prefer squash or rebase according to repository policy; do not force-push shared branches.
- Never commit secrets, generated artifacts, local environment files or unrelated changes.
